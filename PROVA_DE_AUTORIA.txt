"O PratiCom é um ERP Condominial Multi-Tenant autônomo, construído em Node.js e

DAOs, gateways de pagamento e despachantes de notificação. Possui 12 CRUDs
canônicos completos e suporte a Linha de Produtos de Software (LPS)."

ARQUIVO 1: server/config/DatabaseSingleton.js
--------------------------------------------------------------------------------
- Papel Arquitetural: Padrão GoF SINGLETON (Instância única de banco de dados).
- Por que foi usado: Evitar travamentos de concorrência de escrita no SQLite
  (SQLITE_BUSY / file locking), garantir o reuso de conexão aberta ('better-sqlite3')
  e forçar a execução imediata de 'PRAGMA foreign_keys = ON'.
- Código Crítico:
  ```javascript
  class DatabaseSingleton {
    constructor() {
      if (DatabaseSingleton.instance) {
        return DatabaseSingleton.instance;
      }
      this.db = new Database(dbPath);
      this.db.pragma('foreign_keys = ON'); // Ativa integridade referencial
      this.applyCompatibilityMigrations();
      this.seedCondominiumModules();
      DatabaseSingleton.instance = this;
    }
    getDb() { return this.db; }
  }
  const instance = new DatabaseSingleton();
  Object.freeze(instance); // Impede qualquer alteração em tempo de execução
  export const db = instance.getDb(); // Export direto da conexão
  ```
- Funções Detalhadas:
  * `constructor()`: Verifica se `DatabaseSingleton.instance` existe. Se não existir,
    instancia o `better-sqlite3`, ativa chaves estrangeiras, executa migrações de
    compatibilidade e semeia módulos dinâmicos.
  * `getDb()`: Retorna o objeto de conexão do banco de dados.
  * `applyCompatibilityMigrations()`: Garante retrocompatibilidade com esquemas antigos
    adicionando colunas ausentes sem destruir dados legados.
  * `ensureUnitUniquenessConstraint()`: Saneia duplicidades históricas e aplica a
    restrição UNIQUE(block_id, number) no SQLite.
  * `seedCondominiumModules()`: Garante que todo condomínio cadastrado tenha os 6
    módulos opcionais registrados na tabela 'condominium_modules'.

- Código Crítico:
  ```javascript
  class AppConfigSingleton {
    constructor() {
      if (AppConfigSingleton.instance) {
        return AppConfigSingleton.instance;
      }
      this.config = {
        port: process.env.PORT || 5000,
        env: process.env.NODE_ENV || 'development',
        dbPath: path.resolve(__dirname, '..', 'condo_database.sqlite'),

    get(key) { return this.config[key]; }
    getAll() { return { ...this.config }; }
  }
  const instance = new AppConfigSingleton();
  Object.freeze(instance);
  export const appConfig = instance;
  ```
- Funções Detalhadas:
  * `get(key)`: Retorna uma propriedade de configuração específica.
  * `getAll()`: Retorna uma cópia defensiva de todo o mapa de configurações.

ARQUIVO 3: server/dao/AbstractTenantDAO.js
--------------------------------------------------------------------------------
- Papel Arquitetural: Padrão GoF TEMPLATE METHOD (Gabarito de Persistência Multi-Tenant).
- Por que foi usado: Centralizar e padronizar o isolamento multi-tenant de todas
  as consultas SQL do sistema. Todos os 8 DAOs herdam desta classe base.
- Código Crítico:
  ```javascript
  export class AbstractTenantDAO {
    constructor() {
      this.db = DatabaseSingleton.getDb();
    }
    getDb() { return this.db; }

    resolveCondominiumId(options) {
      if (options === undefined || options === null) return null;
      const raw = typeof options === 'object' ? options.condominiumId : options;
      const parsed = parseInt(raw, 10);
      return Number.isInteger(parsed) && parsed > 0 ? parsed : null;
    }

    unitTenantScope(options, { blockAlias = 'b', unitAlias = 'u' } = {}) {
      const condoId = this.resolveCondominiumId(options);
      if (!condoId) return { sql: '', params: [] };
      if (condoId === 1) {
        return {
          sql: ` AND (${blockAlias}.condominium_id = 1 OR ${unitAlias}.block_id IS NULL)`,
          params: []
        };
      }
      return {
        sql: ` AND ${blockAlias}.condominium_id = ?`,
        params: [condoId]
      };
    }

    directTenantScope(options, { tableAlias = '', columnName = 'condominium_id' } = {}) {
      const condoId = this.resolveCondominiumId(options);
      if (!condoId) return { sql: '1=1', params: [] };
      const prefix = tableAlias ? `${tableAlias}.` : '';
      if (condoId === 1) {
        return {
          sql: `(${prefix}${columnName} = 1 OR ${prefix}${columnName} IS NULL)`,
          params: []
        };
      }
      return {
        sql: `${prefix}${columnName} = ?`,
        params: [condoId]
      };
    }
  }
  ```
- Funções Detalhadas:
  * `resolveCondominiumId(options)`: Normaliza o ID do condomínio, tratando tanto
    números puros (`1`) quanto objetos de contexto (`{ condominiumId: 1 }`).
  * `unitTenantScope(...)`: Gera dinamicamente cláusulas SQL com JOINs entre unidades
    e blocos, garantindo isolamento relacional mesmo em dados legados (ID 1).
  * `directTenantScope(...)`: Gera dinamicamente filtros diretos `WHERE condominium_id = ?`
    para tabelas que possuem a coluna de tenant explícita.

  ```javascript
      return true;
    }
    checkRequiredFields(data) { ... }
    checkTemporalConstraints(data) { /* Hook */ }
    checkUniquenessAndConflicts(data, context) { /* Hook */ }
    checkRelationalIntegrity(data, context) { /* Hook */ }
  }

  export class ReservationConflictValidator extends AbstractBusinessValidator {
    constructor(db) { super(); this.db = db; }

    checkTemporalConstraints(data) {
      // Bloqueia reservas em datas passadas e força duração exata de 1 hora
      ...
    }

    checkUniquenessAndConflicts(data, context) {
      let sql = `
        SELECT COUNT(*) as count FROM reservations
        WHERE space_id = ? AND reservation_date = ? 
        AND UPPER(status) IN ('CONFIRMED', 'CONFIRMADA')
  ```

    fórmula matemática de colisão de intervalos temporais:
    `start_time < novo_fim AND end_time > novo_inicio`.

--------------------------------------------------------------------------------
- Papel Arquitetural: Padrão GoF TEMPLATE METHOD (Processamento Financeiro).
- Por que foi usado: Garantir que qualquer meio de pagamento (Pix, Cartão, Boleto)

- Código Crítico:
  ```javascript
  export class AbstractPaymentProcessor {
    processPayment(paymentDetails) {
      this.validateAmount(paymentDetails.amount);
      this.assertAccountStatus(paymentDetails);
      const transactionId = this.processTransfer(paymentDetails);
      const receipt = this.generateReceipt(paymentDetails, transactionId);
      return { success: true, transactionId, receipt };
    }
  }
  ```
- Subclasses:

  * `CondoFeePaymentProcessor`: Valida vinculação da unidade e lança débito na cota condominial.
  * `CardPaymentProcessor`: Simula autorização de adquirente de cartão de crédito.

- Papel Arquitetural: Padrão GoF FACTORY METHOD (Fábrica Central de DAOs).

  ```javascript
  export class DAOFactory {
    static getDAO(type) {
      switch (type.toLowerCase()) {
        case 'resident':
        case 'unit': return new ResidentDAO();
        case 'delivery': return new DeliveryDAO();
        case 'financial': return new FinancialDAO();
        case 'access': return new AccessDAO();
        case 'reservation': return new ReservationDAO();
        case 'market': return new MarketDAO();
        case 'announcement': return new AnnouncementDAO();
        case 'condominium':
        case 'block': return new CondominiumDAO();
        default: throw new Error(`Tipo de DAO desconhecido: ${type}`);
      }
    }
  }
  ```

ARQUIVO 10: server/services/factories/PaymentProcessorFactory.js
--------------------------------------------------------------------------------
- Papel Arquitetural: Padrão GoF FACTORY METHOD (Fábrica de Processadores de Pagamento).
- Por que foi usado: Permitir que o checkout do Mercadinho aceite novos métodos de
  pagamento (Pix, Cartão, Boleto) sem alterar uma única linha do código de checkout.
- Código Crítico:
  ```javascript
  export class PaymentProcessorFactory {
    static createProcessor(paymentMethod) {
      const normalized = String(paymentMethod || '').toLowerCase();
      switch (normalized) {
        case 'pix': return { code: 'PIX', processor: new PixPaymentProcessor() };
        case 'credit_card':
        case 'card': return { code: 'CARD', processor: new CardPaymentProcessor() };
        case 'condo_bill':
        case 'condo_fee': return { code: 'CONDO_FEE', processor: new CondoFeePaymentProcessor() };
        default: throw new Error(`Forma de pagamento não suportada: ${paymentMethod}`);
      }
    }
  }
  ```

    Se um módulo estiver desativado no condomínio, retorna `null` para a métrica sem quebrar a rota.

ARQUIVO 21: server/middleware/moduleGuard.js
--------------------------------------------------------------------------------
- Papel Arquitetural: Interceptador de Segurança de Módulos (Guard / Policy).
- Como funciona:
  ```javascript
  export const checkModuleAvailability = (moduleKey) => (req, res, next) => {
    const condominiumId = req.condominiumId;
    const condoDAO = DAOFactory.getDAO('condominium');
    if (!condoDAO.isModuleEnabled(condominiumId, moduleKey)) {
      return res.status(403).json({
        error: `Acesso negado: o módulo '${moduleKey}' está desativado para este condomínio.`,
        module: moduleKey,
        disabled: true
      });
    }
    next();
  };
  ```

8. ROTEIRO DE PERGUNTAS E RESPOSTAS TÉCNICAS DE CÓDIGO (Q&A)
================================================================================

P1: "Mostre no código onde o Singleton impede a criação de mais de uma conexão."
R1: "Em server/config/DatabaseSingleton.js, linhas 17-19: no constructor da classe,
verificamos se `DatabaseSingleton.instance` já existe. Se existir, retornamos a
instância existente imediatamente sem chamar `new Database()`. Além disso, na
linha 177 executamos `Object.freeze(instance)` para blindar a referência."

P2: "Como você provou que o sistema reutiliza código através do Template Method?"
R2: "Em server/dao/AbstractTenantDAO.js, implementei os métodos `unitTenantScope`
e `directTenantScope`. Todos os 8 DAOs herdam de AbstractTenantDAO via `extends`.
Quando o ResidentDAO ou FinancialDAO precisa filtrar por condomínio, eles apenas
chamam `this.unitTenantScope(condominiumId)`, reutilizando 100% da lógica de
montagem de SQL sem duplicar código."

P3: "Onde está a garantia de que duas reservas não colidem?"
R3: "Em server/services/templates/BusinessValidatorTemplate.js, na classe
`ReservationConflictValidator`, método `checkUniquenessAndConflicts()`. O código
executa uma consulta SQL com a condição:
`WHERE space_id = ? AND reservation_date = ? AND start_time < ? AND end_time > ?`
Se o retorno for maior que 0, lançamos exceção de conflito de horário antes da
gravação no banco."

P4: "O que impede que uma compra no PDV deixe o estoque negativo se o pagamento falhar?"
R4: "Em server/dao/MarketDAO.js, método `checkout()`, encapsulei a validação de
saldo, a baixa de estoque, o processamento de pagamento e o INSERT dos itens dentro
do bloco `this.db.transaction(() => { ... })`. Se o processador de pagamento
(PaymentTemplate) lançar qualquer erro, a transação inteira do SQLite sofre
Rollback automático, restaurando o estoque original."

P5: "Como funciona a segurança multi-tenant no sistema?"
R5: "Implementamos Row-Level Multi-Tenancy. O middleware do Express intercepta o
condomínio ativo e injeta no `req.condominiumId`. As consultas dos DAOs usam os
métodos de escopo de `AbstractTenantDAO`, garantindo que um condomínio nunca enxergue
ou altere blocos, moradores, veículos ou finanças de outro."
